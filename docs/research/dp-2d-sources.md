Method. Each file was fetched with `curl` from `raw.githubusercontent.com/<org>/<repo>/<sha>/<path>` at the pinned commit, and line numbers were read from the fetched file with `awk` and `sed -n`, never from memory. Every quoted string and code block in a Chapter was checked by a script against the fetched lines its link cites: whitespace, punctuation and comment markers were ignored in the comparison, so the words and their order are what was compared. A permalink cites the narrowest range that holds the quoted words. Where the source is markup (comment markers in C and Python, the DocBook tags in `fuzzystrmatch.sgml`), the quote column says what was dropped. The PostgreSQL documentation is cited as its SGML source in the same commit (`doc/src/sgml/fuzzystrmatch.sgml`), which is the documentation for 17.0. The Hunspell and liblqr READMEs are cited in the same commits. Source types: 1 = source code, 2 = official documentation, 3 = standard or original paper, 4 = a post by the system's own engineers. The Avidan and Shamir paper, which liblqr's source names, was not fetched (its address, `faculty.idc.ac.il/arik/imret.pdf`, answered with an HTML page, not the paper); the Chapter cites only what liblqr's own source says about it. Every link is listed unticked in the Topic's section of `docs/research/human-review-queue.md`.

## Observed, not cited

- **The Reference Code and the oracle.** The expected output of every Test comes from other implementations than the Reference Code: suffix-direction tables or memoised recursion (`common`, `trace`, `seam`, `ties`, `edit`, `within`, `weave`, `ways`), a dictionary over reachable sums (`keep`, `signs`), and brute force over every subsequence, seam, subset, coin count, sign assignment or interleaving for small cases, plus Dijkstra over edited strings for small `edit` cases. The oracles were cross-checked against each other on 300 random small cases before the Tests were written. For `trace`, every expected word was also checked to be a common subsequence of the right length, and its exact letters come from the walk the statement defines. Python, TypeScript (Node) and Go were run on every Test in each Problem's Submit scope by the content check.
- **Arithmetic in the Chapters.** The 3^(h−1) seams of an `h`-row grid, the 2 × 9 − 0 = 18 score of `definately` against `definitely`, the 10-against-14 greedy example of the knapsack Chapter (the first Example of `keep`), and the 255 × 255 = 65,025 cells of PostgreSQL's cap were computed, not quoted, and are labelled as arithmetic in the text.
- **Reading, not quotation.** Sentences that say what a line of code does (for example that a cell reads three cells, that PyTorch's weight is the normalised size and its value the estimated runtime, or that liblqr's update window can grow to a whole row) are the agent's reading of the cited lines, and are labelled "reading" in the Chapter where they are not plain.

## Leads that changed

- The issue's lead for Chapter 1 was "the diff algorithms behind version control, spell-check distance". No source was found for a table over two sequences in a version-control diff (the original diff papers were not fetched), so the Chapter reads a spell checker instead: Hunspell's `lcs` and `lcslen`, whose source fills a table of lengths and a table of directions and walks back. The Edit Distance Problem moved to Chapter 4.
- Chapter 2 ("Grid paths") had no lead in the issue. It reads liblqr, a seam-carving library whose source defines its minimum-energy grid in a comment and updates it in place after each seam.
- Chapter 3 ("Knapsack-style tables") had no lead in the issue. It reads PyTorch's `dp_knapsack`, the default solver of the memory-budget setting of its partitioner.
- Chapter 4 ("Rolling rows to save space") would have read git's `levenshtein.c`, but the 1-D Topic's Chapter `dp-1d-git` already reads lines 11 to 14 of that file. This Chapter reads PostgreSQL's `levenshtein.c`, which keeps two rows, and links to `/chapters/dp-1d-git` for the three-row version.
- Candidate Problems used: Longest Common Subsequence (`common`, and `trace`, which adds the walk back), Edit Distance (`edit`, with separate insert, delete and replace costs, and `within`), Coin Change II (`ways`), Target Sum (`signs`), Interleaving String (`weave`). Candidate Problem not used: Unique Paths. A count of right and down routes through a grid has no real system in this Topic to be framed by without an unsourced claim; the counting form lives in the Extra `ties`, which counts seams of the same cost.
- Outline entries: all four became Chapters. None was folded into another.
- Claims cut or rewritten while drafting, for lack of a source: that most misspellings are one slip from a dictionary word (cut); that squeezing every row distorts an image, and that a seam is removed so that "the picture hardly changes" (cut); that an energy "says how much removing a pixel would cost" (rewritten as the price of putting the cell in a seam, with the library's own words for the energy).
