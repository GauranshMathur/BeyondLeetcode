Method. Code and documentation files were fetched with `curl` from `raw.githubusercontent.com/<org>/<repo>/<sha>/<path>` and line numbers read with `grep -n` and `awk 'NR>=a && NR<=b'` on the fetched file. The CPython and pip documentation are linked as their source files (reST in `Doc/library/`, Markdown in `docs/html/topics/`) at the pinned commit, so a line range can be cited; the quote column says where reST or Markdown markup was dropped. Knuth's paper was fetched as a PDF (the fetched `/pdf/cs/0011047` and `/pdf/cs/0011047v1` are byte-identical) and its text extracted with `pypdf`; the "line numbers" for it are the PDF's page numbers, which are the paper's printed page numbers, and the link is `#page=N`. Every quoted string in the Chapters was checked by a script against the fetched text of the cited line range or page (whitespace normalised, comment markers and ligatures mapped); the same script checked that every external link in a Chapter is in the tables below and the other way round. Source types: 1 = source code, 2 = official documentation, 3 = standard or original paper, 4 = a post by the system's own engineers.

## Observed, not cited

- **Oracles.** The expected outputs of every Test were produced by the Python Reference Code and then checked against a second implementation that uses other techniques: `match` against an enumeration of every combination of alternatives (itertools `product`), `cost` against a reachable-state count by search for the cases where the pattern does not match, `resolve` against a brute force over every assignment of a version or none to every package (the answer must satisfy every requirement, and `conflict` only when no assignment does), `subsets`, `perms` and `sums` against `itertools.combinations`, `permutations` and `combinations_with_replacement` sorted on positions, `queens` against a brute force over column permutations, `cuts` against all 2^(n-1) cut sets, `find` against an enumeration of all simple paths, and `exact` against every subset of rows (the set of solutions; the node counts come from the Reference Code and were hand-traced for the paper's matrix: 6 nodes). The oracle script is not committed.
- **Tests that catch a missing undo.** The `find` Tests include a grid where a version without the undo gives `no` and the right answer is `yes` (found by random search over small grids). The `resolve` Tests include a case where forgetting to take back a failed pin's requirements gives `conflict` instead of `ok a=2 b=1`, and one where skipping the check against a package that already has a version gives a wrong answer. The `exact` Tests include two matrices where choosing the lowest open column instead of the fewest gives a different node count (6 against 7, and 9 against 10).
- **Reference Code.** Python, TypeScript (Node) and Go are run on every Test in the Problem's scope by the content check.
- **Worked examples in the Chapters.** The counts in the Chapters (`(a|ab)(c|bc)` on `abc` answering `a` then `bc`, `cost (a|aa)(a|aa)b aaaa` giving `plain 7 visited 6`, the 8 subsets of `1 2 3`) are the Chapters' own arithmetic and are the Tests' expected outputs.

## Leads that changed

- Chapter 1 (the decision tree and the choose, explore, undo loop) had no lead in the issue. The Chapter reads the `BRANCH` opcode of CPython's `re` engine and the documentation's rule for the order of alternatives.
- Chapter 2 (pruning) had no lead in the issue. The Chapter reads the bit vector of Go's regexp backtracker. The issue's lead for Chapter 3, "regex matching", is split: CPython's engine is Chapter 1 and Go's is Chapter 2.
- Chapter 3's other lead, "a dependency solver", is pip's resolver (resolvelib 1.0.1, vendored in pip 24.2).
- Chapter 4 (subsets, permutations and combinations) had no lead in the issue. The Chapter reads the documentation of CPython's `itertools` as a specification: the order and the count it promises, not its implementation.
- Chapter 5 (constraint puzzles) had no lead in the issue. The Chapter reads Knuth's paper on dancing links, which describes Dijkstra's queens program and Algorithm X. No program or source file is cited for it: only the paper. Google's OR-Tools documents backtracking for N-queens, but its page is a live, unversioned page, so it was not used.
- Candidate Problems: all six are in the Topic. Subsets (`subsets`), Permutations (`perms`) and N-Queens (`queens`) are Core. Combination Sum (`sums`), Word Search (`find`) and Palindrome Partitioning (`cuts`) are Extra, because each is a branch off the Build's data (a loaded list, a grid, a word) rather than a step the next Problem needs. None is left out.
