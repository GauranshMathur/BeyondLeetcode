Method. Every source was fetched by the agent in this session: code with `curl` from `raw.githubusercontent.com/<org>/<repo>/<sha>/<path>`, the Python page as HTML from `docs.python.org`. Line numbers were read off the fetched files with `grep -n` and `awk`. A script (`checkquotes`, kept in the agent's scratch folder, not in the repo) then walked every Chapter, statement and Solution, took each quoted string of 12 or more characters and each inline code span that copies code, found the link that follows it in the same paragraph, and checked that the words appear, in order, inside that link's line range of the fetched file (whitespace collapsed, comment markers and macro-continuation backslashes dropped, HTML tags dropped and entities decoded). It reported no quote outside its range. Ranges are narrowed to the quoted words where the quotes are one sentence; where one link supports several quotes, its range is the smallest that holds all of them. Source types: 1 = source code, 2 = official documentation, 3 = standard or original paper, 4 = a post by the system's own engineers. The `rbtree.rst` file is the kernel's own documentation at the pinned commit (type 2). "Quote checked" means the agent fetched the source and the quote is exact; no human has opened these links yet, and each is listed in `docs/research/human-review-queue.md`.

## Observed, not cited

- **Oracles.** The expected outputs of every Test come from two oracles written with other techniques than the Reference Code: a set of integer points (small coordinates, one integer at a time), and elementary segments between every endpoint (any coordinates). The two agreed with each other on 3,000 random command streams; the second is used for Tests with large coordinates or long streams. `find` and `depth` are brute force over all intervals; `rooms` is a scan over the rooms in use. These are observations about this project's Problems, not claims in a Chapter.
- **Reference Code.** Python (on the host's 3.14 and in the Sandbox's 3.13), TypeScript (`node` and `tsc --strict`) and Go (`go vet`, `gofmt`, and each build run in the Sandbox Go image) were run on every Test in the Problem's Submit scope, then by the content check (`content-check.sandbox.test.ts`) in the real Sandbox. A further 360 random streams each in Python and TypeScript were compared with the oracle for the three Problems that have a command no other Problem has (`gaps`, `cut`, `rooms`); Go got the same Tests and the content check.
- **Output size.** A first version of the Tests had two outputs of more than 64 KiB, which the Sandbox cuts (`outputCapBytes`); the content check showed Wrong Answer for it. The Tests were regenerated with outputs under 20 KiB.

## Leads that changed

- The issue's outline has four Chapters: "Sorting and merging ranges", "Interval trees in a real system (lead: the Linux kernel's interval tree, calendar free/busy)", "Sweep line and counting overlaps" and "Meeting-room style resource allocation with a heap". Chapter 1 reads Go's regexp parser (`cleanClass`), found by searching for a standard-library function that sorts ranges and merges the ones that touch. Chapter 3 reads the kernel's interval tree, the issue's lead; the calendar free/busy lead has no source read and is not claimed. Chapter 4 reads `e820__update_table` for the sweep line, found by looking in the kernel for code that walks the start and end points of ranges in order.
- A Chapter was added: Chapter 2 reads Linux's `memblock`, which keeps its list of regions in order and merged on every addition. It carries the candidate Problem Insert Interval, which the outline had no Chapter for.
- The outline's fourth entry, "Meeting-room style resource allocation with a heap", has no real system that the agent found, so it is a section of Chapter 4 and the Extra Problem `intervals-rooms`, with a heap from the Python and Go libraries (cited). The Chapter says so.
- Candidate Problems not in this Topic: Non-overlapping Intervals (the earliest-finish rule of interval scheduling: Greedy found no system for it either, and none turned up among the sources read for this Topic) and Meeting Rooms (it asks whether `depth` is at most 1, which `depth` already answers, so it has no Problem of its own). Insert Interval is the Core Problem `intervals-place`, Merge Intervals is `intervals-merge`, and Meeting Rooms II is the Extra `intervals-rooms`.
