Method. Every file was fetched by the agent with `curl` from `raw.githubusercontent.com/<org>/<repo>/<sha>/<path>` on 2026-10-28. Tags were resolved to commits with `gh api repos/<org>/<repo>/git/ref/tags/<tag>`, and a second call `git/tags/<sha>` for annotated tag objects. Line numbers were read off the fetched files. The documentation page was fetched as HTML and read as text. Every quoted string in the Chapters is listed in the tables below. Source types: 1 = source code, 2 = official documentation, 3 = standard or original paper, 4 = a post or talk by the system's own engineers. ## Observed, not cited

- **Reference Code.** Python, TypeScript (Node) and Go were run on every Test in the scope of each Problem before the content check. The Go binaries were built in the Sandbox image and run on the host.
- **The oracle.** The expected outputs of every Test come from CPython's own `heapq` (pure counting wrapper around the real library, on the host's Python 3.14), which the Reference Code agreed with on random command sequences: at least 300 per Problem in Python, 120 in TypeScript and 150 in Go for each of the seven Core Problems, with `cmp` compared too until `update` and `cancel` came in (the oracle fixes an item with `heapq`'s private `_siftup` and `_siftdown`, which makes one comparison more than the Build, so those sequences leave `cmp` out). `heaps-median` was compared with `statistics.median_low` on 200 random sequences in each Language, and `heaps-arity` with a separate classic d-ary heap on 200 random sequences in each Language. The oracle's clean-up in `heaps-drop` is asyncio's own `_run_once` logic written out with `heapq`, with the number of dropped entries counted exactly.
- **Tests that kill mutants.** Twelve wrong versions of the Reference Code were run against the Tests of their Problem: no ticket, the textbook move down under `cmp`, `init` as repeated pushes, `>=` in `keep`, `<` in `advance`, `fix` without the move up, a rebuild at 100 items instead of over 100, a rebuild at exactly half, no clean-up of the head, a new ticket on `update`, a `keep` that never ignores, and an `init` that restarts the tickets. Eight failed at once. Four survived until a search for an input that tells them apart found one, and each of those inputs was added as a Test (equal keys in `heaps-push-pop`, `cmp` after ignored equal keys in `heaps-keep`, `update` among equal times in `heaps-update-cancel`, and `init` followed by pushes of the same key in `heaps-init`). Giving no ticket to an ignored push in `keep` cannot be told apart by any input, because the tickets that matter keep their order, so the statement's wording there is a definition and has no Test.
- **Review fixes.** A Codex pass on the diff found: intro sentences that described a system without a link next to them (reworded to say only what the Chapter reads, or given a link); a `keep` statement that promised the `N`-th largest even after a `pop`, and left `keep` with `init` undefined (now stated: the promise holds in an input without `pop` or `init`, and an input with `keep` never uses `init`); a Go `bufio.Scanner` that stops on a line over 64 KiB (the Go Reference Code now has a 16 MiB line limit); no Test for `update` or `cancel` after a `drop`, and none with a blank line (added to `heaps-drop` and `heaps-push-pop`); and Big-O formulas that read zero for a limit of 1 (`O(m (1 + log N))`). It also asked for an expected label on the map work in `drop` and a label on `show`. Each was fixed. The content check was run again after the fixes.
- **Largest Submit.** The Submit with the most hidden Tests is `heaps-drop`, the last Core Problem: 43 Tests, in two batches (25 and 18). The largest Extra Problem Submit is `heaps-arity`, 35 Tests. The limit is 50.

## Arithmetic and reading that the Chapters label as theirs

- The parent of position `p` is `(p - 1) // 2`, and a heap of `n` items has ⌊log2 n⌋ rows above the last item (Chapter 1).
- A push is O(log n) comparisons in the worst case, and the `append` inside it is amortised O(1) (Chapter 1; the amortised claim is the Dynamic arrays Topic's).
- The worked pop on the 7-item heap `1 3 2 7 4 5 6`: 3 comparisons with the textbook move, 2 with `heapq`'s, the same array, and `cmp` 8 in the Build (Chapter 1). The oracle printed 6 before the pop and 8 after.
- Why `Init` is linear: about `n / 2^(h+1)` items at height `h`, and the sum of `h × n / 2^(h+1)` is `n`; and pushing in descending order is O(n log n) (Chapter 2).
- `nlargest` is O(n + m log n) comparisons in the worst case and O(n) space; an item equal to `top` does not replace it because the test is strict (Chapter 3).
- 21 items fill 3 rows with four children and need 5 rows with two; comparisons per row in Go's `siftdownTimer` against a binary move down (Chapter 4).
- A restarted libuv timer goes to the back of its ties, read off `uv_timer_start`; Kubernetes' `Fix` and `Remove` are O(log n) as the Go documentation says; the lazy-deletion cost, O(1) amortised per cancel, is the Chapter's own argument (Chapter 5).
