Method. Each file was fetched with `curl` from `raw.githubusercontent.com/<org>/<repo>/<sha>/<path>` at the pinned commit, and line numbers were read from the fetched file with `awk` and `sed -n`, never from memory. Every quoted string in a Chapter or statement, and every code block, was checked by a script against the fetched lines its link cites: whitespace and punctuation were ignored in the comparison, so the words and their order are what was compared. Where the source is markup (reST roles and emphasis in `functools.rst`, WEB markup bars and quotation marks in `tex.web`, comment markers in C), the quote column says which markup was dropped. A permalink cites the narrowest range that holds the quoted words. The documentation of CPython is cited as its reST source in the same commit (`Doc/library/functools.rst`), which is the documentation for 3.13.0. Source types: 1 = source code, 2 = official documentation, 3 = standard or original paper, 4 = a post by the system's own engineers. Every link is listed unticked in the Topic's section of `docs/research/human-review-queue.md`.

## Observed, not cited

- **The Reference Code and the oracle.** The expected output of every Test comes from a second implementation that uses other techniques, not from the Reference Code: `functools.lru_cache` and `cache_info()` for `cache`, brute force over every layout, subset or cut for small cases of `wrap`, `tolerant`, `pick`, `spread`, `decode` and `vocab`, memoised recursion for larger ones, and a breadth-first search over amounts for `fewest`. The two kinds were cross-checked against each other on 300 random small cases per command before the Tests were written. Python, TypeScript (Node) and Go were run on every Test in each Problem's Submit scope locally, then by the content check.
- **Arithmetic in the Chapters.** The call counts of a plain `fib` recursion (1,973 for `fib(15)`, 331,160,281 for `fib(40)`), the 44 calls and 28 hits of the documentation's `fib` example, and the cube arithmetic in the TeX Chapter (27 + 27 = 54 against 216) were computed, not quoted, and are labelled as arithmetic in the text.
- **The greedy example.** `load 4 1 2 4`, `wrap 6` costs 16 optimally and 64 greedily, found by search over small words and checked by hand in the statement.

## Leads that changed

- The issue's lead for Chapter 2 was "how a text-wrapping or tokenising routine picks breaks". The Chapter reads TeX's line breaking, whose source says in words what the recurrence is. Tokenising went to Chapter 4.
- Chapters 1, 3 and 4 have no lead in the issue. Chapter 1 reads `functools.cache` because its documentation counts hits and misses on a recursive example. Chapter 3 reads git's `levenshtein.c`, which keeps three rows of a table and says so in a comment. It is a two-dimensional table, so the Chapter says so and applies the decision to a one-dimensional recurrence. Chapter 4 reads SentencePiece's unigram lattice, where `Viterbi` and `ForwardAlgorithm` are the same loops with a maximum and a sum.
- The same file, git's `levenshtein.c`, is the natural source for the 2-D Topic's rolling-rows Chapter (issue #253). This Topic uses it first; C121 may want another source or a different part of the file.
- Candidate Problems not in this Topic: Longest Increasing Subsequence. None of the four systems uses it, so no Chapter can frame it by a real system without an unsourced claim. Climbing Stairs is `ways`, House Robber is `pick` (generalised by `spread`), Coin Change is `fewest`, Decode Ways is `decode`, and Word Break is the Extra Problem `vocab`, which counts the cuts and finds the fewest pieces instead of answering yes or no.
- Outline entries: all four became Chapters. None was folded into another.
