Method. Every source was fetched by the agent in this session: code from `raw.githubusercontent.com/<org>/<repo>/<sha>/<path>`, the RFC as text and as HTML from `rfc-editor.org`, the Python documentation as HTML from `docs.python.org`. Line numbers were read off the fetched files with `grep -n` and `sed -n`. A script then checked every quoted string in the Chapters and statements against the fetched text (whitespace collapsed, C comment markers dropped, HTML tags dropped and entities decoded) and against the line range of the link that follows the quote, and narrowed each range to the quoted words. The RFC's HTML has anchors only for its top-level sections (`#section-3` for section 3.2.1), so RFC links name the section in the text and the quote column gives the line numbers in the text version (`rfc1951.txt`). Source types: 1 = source code, 2 = official documentation, 3 = standard or original paper, 4 = a post by the system's own engineers. "Quote checked" means the agent fetched the source and the quote is exact; no human has opened these links yet, and each is listed in `docs/research/human-review-queue.md`.

## Observed, not cited

- **Oracles.** The expected outputs of every Test come from a second implementation that uses other techniques than the Reference Code: `cidr` from trailing-zero counts (the way CPython does it), checked against a dynamic program on all ranges inside 0 to 63; `huffman` from the two-queue method on sorted weights, checked against an exhaustive search over trees on 300 random small inputs; `edf` from sorting, checked against every permutation on 400 random small job lists; `ontime` from a dynamic program over job counts, checked against every subset; `greedy` and `lazy` from a port of zlib's `deflate_slow` state machine (`prev_length`, `match_length`, `match_available`), which agrees with the plain rule on 3,000 random tables; `reach` from a dynamic program over every jump length. The maximum number of blocks over every range of 8-bit numbers is 14 (2 x 8 - 2), which fits the Chapter's "at most `w + 1` sizes in each of two phases" bound.
- **Reference Code.** Python, TypeScript and Go are each run on every Test in the Problem's Submit scope by the content check (`content-check.sandbox.test.ts`) in the real Sandbox.

## Leads that changed

- The issue's outline has four Chapters: "When a local choice is provably safe, and the exchange argument", "Prefix codes in a real compressor (lead: Huffman coding in DEFLATE)", "Scheduling and interval choices" and "Counter-examples where greedy fails". Chapter 1 reads CPython's `ipaddress.summarize_address_range`, found by searching for a standard-library function that picks the biggest block that fits; its exchange argument is the Chapter's own and the Chapter says so. Chapter 2 is the issue's lead (DEFLATE, with zlib's `trees.c` as the code). Chapter 3 reads Linux's deadline scheduler for the scheduling half of the outline. The interval half has no system in this Topic: no real system was sourced for the earliest-finish rule of interval scheduling, so it is not claimed. Chapter 4 reads zlib's lazy matching, a real greedy rule and its patch; the claim that neither rule is always better rests on the Problem's tables, which the Chapter labels as its own.
- Candidate Problems not in this Topic: Maximum Subarray, Jump Game (a variant is the Extra Problem `reach`, which is Jump Game II with the jump lengths a match allows), Gas Station, Hand of Straights and Partition Labels. Maximum Subarray is a running-sum scan, not a choice with an exchange argument, and no real system of the four above frames it. Gas Station, Hand of Straights and Partition Labels have no real system to frame them. `reach` stands in for the Jump Game family, framed by zlib's token parse.
