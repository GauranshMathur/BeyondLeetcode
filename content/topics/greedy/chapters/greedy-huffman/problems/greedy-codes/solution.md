Drop the zeros. If nothing is left print `0`. If exactly one item `f` is left, print `f`: it gets one bit each time. Otherwise put the items in a min-heap, and while there are two or more: pop the two smallest, `a` and `b`, add `a + b` to `total`, and push `a + b`. Print `total`.

**Why the two lightest are safe.** Take a best prefix code, as a tree with every inner node having two children (a node with one child can be removed to shorten the code). Let `a` and `b` be the two lightest symbols. Some deepest inner node has two leaves, `x` and `y`. If `a` is not at the deepest level, swap it with a leaf there: `a` is no heavier, so moving it deeper and the heavier leaf up cannot raise the cost. The same for `b`, and then make `a` and `b` siblings (the other leaf at that node can swap places with `b` in the same way). So some best code has `a` and `b` as siblings at the greatest depth, and the best code for the rest is the best code of the list in which `a` and `b` are replaced by one symbol of weight `a + b`. In that code the new symbol's leaf is one level above where `a` and `b` sit, so the real cost is the smaller cost plus `a + b`. Repeating the choice gives the cost as the sum of every merged weight.

**Cost.** Each step is a heap pop of two and a push of one, `O(log n)` in the **worst case** each, and there are `n - 1` steps: O(n log n) in the **worst case** for `n` symbols, O(n) extra space. The total is at most the sum of the items (at most 10^10) times the number of merges (below 10^4), under 10^14, which is below 2^53, so a 64-bit integer or a JavaScript number holds it.
