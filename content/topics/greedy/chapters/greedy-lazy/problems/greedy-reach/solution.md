Let `jumps = 0`, `end = 0`, `far = 0`. For `i` from 0 to `n - 1`: set `far = max(far, i + max(1, values[i]))`; if `i == end`, add 1 to `jumps` and set `end = far`. Print `jumps` (0 for an empty table).

**Why it is right.** Because a match may be cut to any shorter length, from every position `p` you can land on every position from `p + 1` to `p + max(1, item)`. So the set of positions reachable in exactly `k` jumps, or fewer, is an interval that starts at 0 (by induction: if the positions reachable in `k` jumps are `0..end_k`, those reachable in `k + 1` are `0..end_{k+1}` where `end_{k+1}` is the maximum landing of any position in `0..end_k`, and every position in between is reachable because from the position that reaches `end_{k+1}` you can also land on every shorter distance). The loop keeps `end` as `end_k` and `far` as the maximum landing so far, which becomes `end_{k+1}` when `i` reaches `end_k` and a further jump is unavoidable. The number of times that happens before `n` is covered is the fewest jumps. The choice that is safe is not the longest jump from the position you stand on, but the jump from whichever position in the current interval lands furthest, and the exchange argument is that any other jump of the same count lands no further.

**Cost.** One pass: O(n) in the **worst case**, O(1) extra space. The same answer from a table of the fewest jumps to each position, filled by looking at each position's whole range, is O(n x 258) in the **worst case**.
