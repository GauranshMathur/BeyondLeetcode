Keep `x = A` and a count of 0. While `x <= B`: find the largest size `s` that is a power of two, divides `x` (`x % s == 0`) and satisfies `x + s - 1 <= B`; add one to the count; add `s` to `x`. Print the count. Finding `s` is a loop that starts at 1 and doubles while the doubled size still qualifies. `x = 0` is a multiple of every power of two, so only `B` limits it, and `cidr 0 4294967295` is one block.

**Why the biggest block is safe.** Suppose the blocks chosen so far match some best list, and `x` is the first number they leave uncovered. The rest of that best list covers exactly `x..B` with blocks that do not overlap, so one of its blocks starts at `x`. Let `2^k` be the largest size that fits at `x`. The block of the best list at `x` is no bigger, say `2^j` with `j <= k`. Every other block of the best list that touches `x..x+2^k-1` lies inside it: a block of 2^m numbers starts at a multiple of 2^m, and if `m` is at least `k` its start would be a multiple of 2^k strictly between `x` and `x + 2^k`, and there is none. So the blocks of the best list inside that stretch can all be replaced by the single block of `2^k` numbers. That is one block in place of at least one, so the list is no longer. The greedy choice can therefore be made first without losing anything. By repetition the whole greedy list is a best one.

**Cost.** The sizes the greedy list uses first strictly rise (while `x` is the limit: after a block of `2^k`, the next `x` is a multiple of `2^(k+1)`) and then strictly fall (while `B` is the limit: the rest is shorter than the block just taken). Each phase uses each of the at most 33 sizes once, so at most 66 blocks, and finding each size takes at most 33 doublings: O(w^2) in the **worst case** for w-bit numbers with this loop, a constant for 32 bits, and O(1) extra space. With a trailing-zero count (as the CPython code does) each block is O(1) and the whole is O(w).
