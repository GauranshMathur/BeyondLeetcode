Give every cell a number, row by row, and start every land cell as its own group, so the count of islands is the number of land cells. For each land cell look at its neighbours to the right and below, and at the two lower diagonals when `C` is `8`; when a neighbour is land, `union` the two cells, and each `union` that merges two different groups takes 1 off the count. The count at the end is the number of islands.

Looking from each cell only at the neighbours that come later in reading order touches every pair of neighbours once. With `N` cells the work is O(N) calls of `union`, each **amortised** O(α(N)), so O(N α(N)) in the **worst case** (amortised) and O(N) space. A breadth-first search from each land cell that is not yet visited gives the same answer in O(N); the Problem uses `union` because it is the structure of the Chapter.

OpenCV's documentation says its function returns "N, the total number of labels [0, N-1] where 0 represents the background label" ([imgproc.hpp, lines 3922 to 3923](https://github.com/opencv/opencv/blob/dad8af6b17f8e60d7b95a1203a1b4d22f56574cf/modules/imgproc/include/opencv2/imgproc.hpp#L3922-L3923)), so the number of land components there is N - 1; this Problem counts land only.
