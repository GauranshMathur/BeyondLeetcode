Keep a stack of nodes to visit and a set of visited ones. Take a node from the stack. If it has been visited, skip it. Otherwise write it down, add it to the set, and push its edges in reverse order, so that the first edge is on top. This visits nodes in the same order as the recursive search: the whole of the first edge's reach comes before the second edge is looked at.

Each node is visited once and each list is read once, but a node can be pushed once per edge that leads to it, so the stack holds O(E) entries in the **worst case**. The time is O(V + E) in the **worst case**. The visited set takes O(V) space.

Compare the two searches on the Example. Both find `d` from `a`, but depth-first goes through `b` and `c` first and a breadth-first search takes the edge `a d`. Depth-first search does not find the shortest route, and the shortest circle is what lockdep's comment says it uses breadth-first search for: "Breadth-first search instead of depth-first search is used in order to find the shortest (circular) path." ([lockdep.c, lines 1449 to 1451](https://github.com/torvalds/linux/blob/ffc253263a1375a65fa6c9f62a893e9767fbebfa/kernel/locking/lockdep.c#L1449-L1451))
