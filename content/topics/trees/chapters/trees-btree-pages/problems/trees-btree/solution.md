A node is a sorted list of keys and a list of children. Adding a key walks down to a leaf, one node per level, and puts the key in. A node with 4 keys splits into a left node with the first key, a key that moves up (the second), and a right node with the last two. The recursion hands the pair back to the parent, which inserts the key and the new child and may split in turn. A root that splits is replaced by a new root with one key. That is the only time the tree gets taller, and it happens at the top, so every leaf stays at the same depth.

This is Rust's split at B = 2: a node holds up to `2B - 1` = 3 keys, and after a split the left node keeps `B - 1` = 1 key. See the Chapter.

Every node except the root holds at least 1 key, so every inner node has at least 2 children. The height is at most log₂(n + 1) in the **worst case**, and at least log₄(n + 1), since a node holds at most 3 keys. Adding a key is a walk down plus at most one split per level on the way back, each a constant amount of work on at most 4 keys, so it is O(log n) in the **worst case**. `bt find` reads one node per level, O(log n) nodes in the **worst case**. Compare that with a chain from the last Chapter: with 200 sorted keys the search tree is a chain of height 200, and the B-tree reads at most 7 nodes.
