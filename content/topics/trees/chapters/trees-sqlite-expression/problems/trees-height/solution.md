The tokens list the tree level by level, so reading them is a breadth-first walk with a queue: the node at the front of the queue takes the next two tokens as its children, and every child that exists joins the back of the queue. That is O(n) in the **worst case** for n tokens. `show` runs the same walk the other way round, writing a token for every child slot of every node, then dropping the trailing `-`.

The height is the recursion from the Chapter. The height of nothing is 0 and the height of a node is `1 + max(height(left), height(right))`. It visits each node once, so it takes O(n) time in the **worst case**, and the recursion goes as deep as the tree is tall, so it needs O(h) stack for height h. An empty tree prints `0`, a single node prints `1`, and a chain of n nodes prints n.
