Walk down the prefix. If any character is missing, the answer is empty. Otherwise take the node reached and visit it and everything below it, depth first. At each node, take its own key first (if it holds a value), then its children in ascending order of their character, each with the whole subtree below it. That visits the keys in the order the statement asks for: a key before the keys that extend it, and sibling subtrees in character order, where digits sort before letters because of their character codes.

`count` is the number of keys that visit finds. The empty prefix needs no special case: the node reached is the root, and every key is below it. This is the walk Redis does in `countChannelsInSlot` (see [Redis Cluster: listing by prefix](/chapters/tries-redis-slots)): reach the start of the prefix, then read forward in key order until the prefix ends.

Cost: reaching the prefix takes O(L) expected time for a prefix of L characters. The visit then touches every node below the prefix, and sorts the children of each. In the **worst case**, with the empty prefix, that is every node: O(N log C) for N nodes with at most C children each (here C is at most 36). A prefix that matches few keys visits few nodes.
