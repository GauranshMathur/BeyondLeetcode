Keep `lo = 0` and `total = 0`. For each index `hi`: add `values[hi]` to `total`. While `total >= S`, record `hi - lo + 1` if it is smaller than the best so far (or if there is no best yet), then subtract `values[lo]` and add one to `lo`. Print the best, or 0 if none was found.

**Why it is right.** Look at one start `s`. Items are positive, so the totals of the runs that start at `s` only grow as the run is extended, and the shortest run from `s` that reaches `S` ends at the first `hi` where it does. The left edge never moves past `s` before that run has been tested: `lo` only advances while the window `lo..hi` still reaches `S`, and when `lo` reaches `s` with `hi` at that first position, the loop records `hi - s + 1` before it moves on. So the shortest run from every start is recorded, and the best of those is the answer. Because `S` is at least 1, a window with total 0 does not reach it, so the loop stops once the window is empty, and `lo` can be at most `hi + 1`.

**Cost.** Each index enters the window once and leaves it at most once: at most 2n steps, so O(n) in the **worst case**, with O(1) extra space. Starting a run at every position and extending it until it reaches `S` is O(n²) in the **worst case**.
