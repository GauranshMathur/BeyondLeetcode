# liblqr: the cheapest seam down an image

An image can be made narrower by scaling every row by the same amount, or by taking something out. The LiquidRescale library, `liblqr`, "provides a C/C++ API for performing non-uniform resizing of images by the seam-carving technique" ([README, lines 20 to 22](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/README#L20-L22)), and its source says it "implements the algorithm described in the paper" "Seam Carving for Content-Aware Image Resizing" by Shai Avidan and Ariel Shamir ([lqr/lqr_carver.c, lines 5 to 7](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L5-L7); the comment markers and line breaks dropped). This Chapter reads `lqr/lqr_carver.c` at the tag `v0.4.3`, the commit `704a319`. What it takes out is a **seam**, a path of cells from the top row to the bottom row, one per row: the library stores a path as one entry for each of the `h` rows (`r->vpath = g_try_new(gint, r->h);`, [line 243](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L243)), and each time it carves one out it makes the image one column narrower (`r->w--;`, [line 757](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L757)).

## A grid of energies, and a grid of costs

Every pixel has an **energy**, which the library's comment below calls "the energy at point (x,y)". Treat it as the price of putting that cell in a seam: a seam costs the sum of its energies, and the cheapest one is the one to take out. Trying every seam is hopeless: a seam can step to up to three cells in the next row, so a grid `h` rows tall has up to 3^(h−1) seams from each start cell (arithmetic, not from the source). The library fills a second grid instead, and its comment defines it:

```
compute auxiliary minpath map
defined as
  y = 1 : m(x,y) = e(x,y)
  y > 1 : m(x,y) = min_{x'=-dx,..,dx} ( m(x-x',y-1) + rig(x') ) + e(x,y)
where
  e(x,y)  is the energy at point (x,y)
  dx      is the max seam step delta_x
  rig(x') is the rigidity for step x'
```

([lqr/lqr_carver.c, lines 614 to 622](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L614-L622); the comment markers dropped) So `m(x, y)` is the cheapest cost of reaching the cell `(x, y)` from the top: its own energy plus the cheapest of the cells in the row above that are at most `dx` columns away. The constructor sets `r->delta_x = 1;` ([line 84](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L84)), and `lqr_carver_init(LqrCarver *r, gint delta_x, gfloat rigidity)` lets a caller change it ([line 227](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L227)). With `dx` of 1 and no rigidity, which is the case this Topic uses, a cell reads the three cells above it: straight up, up-left and up-right.

The code fills it row by row. The first row is a copy of the energies, `r->m[data] = r->en[data];` ([line 640](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L640)). For every other row it first works out which neighbours exist, under the comment "watch for boundaries", with `x1_min = MAX(-x, -r->delta_x);` and `x1_max = MIN(r->w - 1 - x, r->delta_x);` ([lines 652 to 654](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L652-L654)), so a cell in the first or last column has only two. It takes the cheapest neighbour's value and adds the cell's own energy: `r->m[data] = r->en[data] + m;` ([line 694](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L694)). Every cell reads at most 2 × `dx` + 1 others, so for a fixed `dx` the whole grid costs O(w × h) time in the **worst case**.

## The way back

Cheapest cost is not yet a seam. The library keeps a second array of the same size beside the first, `r->m = g_try_new(gfloat, r->w * r->h)` and `r->least = g_try_new(gint, r->w * r->h)` ([lines 240 to 241](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L240-L241)), and records in `least` which cell above was the cheapest, `r->least[data] = data_down;` ([lines 664 to 690](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L664-L690), where the loop that follows replaces it when a later neighbour is cheaper). It is the same pair of tables as Hunspell's lengths and directions in [the previous Chapter](/chapters/dp-2d-hunspell). To read out a seam, `lqr_carver_build_vpath` first looks along the bottom row, "span the last row for the minimum mmap value" ([line 1273](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L1273); the comment markers dropped), and then goes up, "follow the track for the other rows" ([line 1292](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L1292)), with `last = r->least[r->raw[y][last_x]];` ([line 1301](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L1301)). The cheapest seam ends in the cheapest cell of the last row, and each `least` entry names the cell before it.

## Not rebuilding the table

Removing one seam is not the end. The library removes seam after seam, and each removal changes the picture. After it computes a seam ("compute vertical seam", [line 747](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L747)) it carves it out with `lqr_carver_carve(r);` ([line 760](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L760)), and then, except on the passes where it switches its left-right preference, does not fill the grid again from scratch. The old call is commented out, `/* lqr_carver_build_mmap (r); */`, and the new one is `LQR_CATCH(lqr_carver_update_mmap(r));` ([lines 768 to 774](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L768-L774); the other branch of that `if` still calls `lqr_carver_build_mmap(r)`). Its comment gives the decision: "this only updates the affected pixels, which start form the beginning of the changed energy region around the seam and expand at most by delta_x (in both directions) at each row" ([lines 1114 to 1118](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L1114-L1118); the comment markers dropped, and "form" is the source's own spelling). The loop widens its window row by row: "make sure to include the changed energy region" and "expand the affected region by delta_x" ([lines 1157 to 1161](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L1157-L1161)), and it shrinks it again where nothing changed: "reduce the range if there's no (relevant) difference with the previous map" ([lines 1222 to 1223](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L1222-L1223)).

The reason follows from the recurrence. A cell reads only cells at most `dx` columns away in the row above ([lines 614 to 622](https://github.com/carlobaldassi/liblqr/blob/704a3194a9a0df7aaddbfa40306583b23407a88b/lqr/lqr_carver.c#L614-L622), the comment quoted earlier), so a changed cell can change the cells below it only within `dx` columns on each side, and the cells outside that window keep their value. This is how a table is reused: know what each cell reads, and recompute only the cells that read something that changed. The window can grow to the whole row, so in the **worst case** an update costs as much as a rebuild, O(w × h); the saving is for changes that stay narrow (reading of the comment, not measured).

## What the Problems build

`grid R C e...` replaces the grid with `R` rows of `C` energies, given row by row. `seam` prints the cost of the cheapest seam, with `dx` of 1 and no rigidity. The Extra Problem `ties` counts the seams that reach that cost, which needs a second table beside the first, like `least` here.
