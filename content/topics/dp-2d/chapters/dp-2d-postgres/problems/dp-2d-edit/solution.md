Keep two rows of `m + 1` cells, where `m` is the length of the first word. The first row is `i * DEL` for `i` from 0 to `m`: turning `i` letters into nothing takes `i` deletions. For each letter `j` of the second word, from 1, start the new row with `j * INS` in column 0 and fill column `i` from 1 with the smallest of three: `prev[i - 1]` plus `SUB` if letter `i` of the first word differs from letter `j` of the second, or plus 0 if they are equal; `prev[i] + INS`; and `curr[i - 1] + DEL`. Then swap the rows. Print the last cell of the last row.

**Why it is right.** The last move of a cheapest edit of the first `i` letters into the first `j` is one of three kinds. A deletion of letter `i` leaves turning `i - 1` letters into `j`. An insertion of letter `j` leaves turning `i` letters into `j - 1`. Otherwise letter `i` ends up as letter `j`, which costs `SUB` unless they are equal and leaves turning `i - 1` into `j - 1`. Each cell is the cheapest of the three. An empty word is the empty string: `m` or the length of the second word is 0 and the initial row or column gives the answer.

**Cost.** Every one of the m × n cells takes O(1), so time is O(m × n) in the **worst case**, and space is O(m): two rows of `m + 1` numbers instead of a table of (m + 1) × (n + 1). The price, as in the Chapter, is that this gives only the cost, not which moves make it.
