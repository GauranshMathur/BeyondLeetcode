Keep a table `c` with `m + 1` rows and `n + 1` columns, where `c[i][j]` is the length of the longest common subsequence of the first `i` letters of the first word and the first `j` of the second. Row 0 and column 0 are 0, since an empty prefix shares nothing. For `i` and `j` from 1: if letter `i` of the first word equals letter `j` of the second, `c[i][j] = c[i - 1][j - 1] + 1`; otherwise `c[i][j]` is the larger of `c[i - 1][j]` and `c[i][j - 1]`. Print `c[m][n]`. An empty word, written `-`, is the empty string, and its row or column is all zeros.

**Why it is right.** If the two last letters are equal, some longest common subsequence ends with that letter: an answer that does not use it can be changed to use it without getting shorter, so the rest is a longest common subsequence of the two shorter prefixes, plus one. If they differ, the last letter of at most one word can be the last letter of the answer, so the answer is the better of dropping the last letter of the first word and dropping the last letter of the second.

**Cost.** There are (m + 1) × (n + 1) cells and each reads at most three, so time is O((m + 1) × (n + 1)) in the **worst case**, and so is space. Only the previous row is ever read here, so two rows would do for the length alone, as the last Chapter shows. This Build keeps the whole table because the next Problem walks back through it.
