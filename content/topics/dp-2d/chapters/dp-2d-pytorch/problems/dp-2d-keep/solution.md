Keep a table with `n + 1` rows and `CAP + 1` columns, where `table[i][j]` is the largest total value from the first `i` items within weight `j`. Row 0 is all zeros. For each item `i` with weight `w` and value `v` and each `j` from 0 to `CAP`, set `table[i][j]` to `table[i - 1][j]`, and if `w <= j`, to the larger of that and `table[i - 1][j - w] + v`. Print `table[n][CAP]`.

**Why it is right.** An optimal set for the first `i` items within weight `j` either leaves item `i`, and is then an optimal set for the first `i - 1` items within `j`, or takes it, and is then item `i` plus an optimal set for the first `i - 1` items within `j - w`. Reading only row `i - 1` means an item is taken at most once. The ratio rule is not enough because the best set can leave out the item with the best ratio, as the Example shows. An item of weight 0 is taken whenever it is read, since `w <= j` always holds and its value is not negative.

**Cost.** The table has (n + 1) × (CAP + 1) cells, each O(1), so time and space are O(n × CAP) in the **worst case**. This is pseudo-polynomial: the table grows with the value of `CAP`, not with the number of digits that write it, which is why the statement caps `CAP` at 5000. Only the previous row is read, so two rows would do for the total, but naming the chosen items, as PyTorch does, needs the whole table.
