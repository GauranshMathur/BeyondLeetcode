# TeX: choosing every line break together

A paragraph is a row of words, and a printer has to cut it into lines of one width. The quick way is to put as many words as fit on the first line, break, and do the same for the next. That is **greedy**, and it can strand a very loose line later because each break was chosen without looking ahead. Donald Knuth's TeX chooses all the breaks of a paragraph together, as one problem over the whole row. This Chapter reads how, in TeX 3.14159265 as it ships in TeX Live 2018.2, in Part 38 of `tex.web`, the program's source with its commentary. The file's banner is "This is TeX, Version 3.14159265" ([texk/web2c/tex.web, line 191](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L191)). The decision is to compute, for each place a line could end, the best way to have reached it.

## One problem, not many

Part 38 begins by naming what it is about: "the mechanism for choosing the best possible breakpoints that yield the individual lines of a paragraph" ([lines 15982 to 15983](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L15982-L15983); the WEB quotation marks around "best possible" dropped). It also says what kind of problem that is: "the line-breaking problem can be regarded as a special case of the problem of computing the shortest path in an acyclic network" ([lines 15996 to 15998](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L15996-L15998)). Read the words as a row with a place between each pair. Every place a line may end is a point, a line from one point to a later one is a step with a cost, and the best paragraph is the cheapest way across. A shortest path in a network whose steps only go forward is a **recurrence over a line**: the cheapest way to reach a point depends only on the cheapest ways to reach the points before it.

## The recurrence in the source

TeX keeps a record for each place a line can end: "An active node and a passive node are created in mem for each feasible breakpoint that needs to be considered." ([lines 16099 to 16101](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16099-L16101); the markup dropped) One field of the active node, `total_demerits`, "is the minimum possible sum of demerits over all lines leading from the beginning of the paragraph to this breakpoint" ([lines 16123 to 16124](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16123-L16124); the markup bars around `total_demerits` dropped). That is the table: one best total per place. The code that fills it, for a line from an earlier break `r` to the current place `cur_p` with cost `d`, reads:

```
d:=d+total_demerits(r); {this is the minimum total demerits
  from the beginning to |cur_p| via |r|}
if d<=minimal_demerits[fit_class] then
  begin minimal_demerits[fit_class]:=d;
  best_place[fit_class]:=break_node(r); best_pl_line[fit_class]:=l;
```

([tex.web, lines 16827 to 16831](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16827-L16831)) Add the line's own cost to the best total at its start, and keep the smallest sum, remembering which break it came from (`best_place`). As a formula on a row of words: `best[j]` is the minimum over every earlier break `i` of `best[i] + cost(i, j)`, with `best[0] = 0` (arithmetic on the loop). TeX's table is wider than that. The source says the algorithm "determines the best possible way to achieve each feasible combination of position, line, and fitness" ([lines 16090 to 16091](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16090-L16091)), so it is indexed by more than the place. The Problems keep only the place.

Not every pair of breaks is tried. A break is kept only if it is **feasible**, "in the sense that there is a way to end a line at the given place without requiring any line to stretch more than a given tolerance" ([lines 16074 to 16076](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16074-L16076)). The same loop skips a line that is too loose: the variable `threshold` is the "maximum badness on feasible lines" ([line 16323](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16323); the comment braces dropped), and the code reads `if b>threshold then goto continue;` ([line 16754](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16754)), which jumps past the step that records a new feasible break ([line 16757](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16757)). A line that is too loose is not a costly step; it is no step at all.

## What a line costs

The cost grows faster than the looseness. The source defines the "badness" of glue "when a total t is supposed to be made from amounts that sum to s" ([lines 2312 to 2313](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L2312-L2313); the tie and markup bars dropped), and says "the badness of this situation is 100(t/s)³" ([lines 2313 to 2314](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L2313-L2314); the source writes the formula in TeX math, `$100(t/s)^3$`, where `^3` is the exponent). For a line, `t` is how far it must stretch and `s` how far it can (the Chapter's reading). The demerits add a penalty per line to the badness and square the sum: `d:=line_penalty+b; if abs(d)>=10000 then d:=100000000@+else d:=d*d;` ([lines 16882 to 16883](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16882-L16883)). A cube makes one very loose line much worse than two a little loose. With a cost of the unused width cubed, as the Problems use, two lines with 3 unused spaces each cost 27 + 27 = 54, and one line with 6 unused and one with none cost 216 + 0 = 216 (arithmetic). That is why the best breaks are not the greedy ones: filling the first line completely can force a worse one later.

## Forgetting breaks

A table of every place would grow with the paragraph. TeX does not keep them all: "We need active nodes only for breakpoints near the place in the paragraph that is currently being examined, so they are recycled within a comparatively short time after they are created." ([lines 16101 to 16104](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16101-L16104)) A record for an earlier break stops being used when a line starting there would be too wide: "If cur_p is too far from an active node, that node is deactivated." ([lines 16329 to 16330](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16329-L16330); the markup bars around `cur_p` dropped) The next Chapter is about that idea: how much of the table the recurrence still reads.

## What the Problems build

The sequence is now a list of word widths, and the Problem `wrap` asks for the total cost of the best layout, with the rules written for this Problem. A line holds one or more words with a single space between neighbours, never wider than `W`, and costs the cube of its unused width; the last line costs nothing. With `n` words and a line holding at most `(W + 1) / 2` of them, the table needs O(n × W) steps in the **worst case** and O(n) space. The Extra Problem `tolerance` adds TeX's idea of a feasible line ([lines 16074 to 16076](https://github.com/TeX-Live/texlive-source/blob/f68b0992e13a2e155d71beb3e016ea4139023224/texk/web2c/tex.web#L16074-L16076)): a line that leaves more than `T` unused is not allowed at all.
