Keep `best[j]`, the cheapest cost of laying out the first `j` words, or "impossible". Start with `best[0] = 0`. For each `j` from 1 to `n`, walk `i` back from `j` to 1, adding the width of word `i - 1` and one space as you go, so you know the width of the line made of words `i - 1` to `j - 1`. Stop when that width is over `W`. Otherwise, if `best[i - 1]` is possible, the candidate is `best[i - 1]` plus the line's cost, which is `(W - width)^3`, or 0 when `j = n`. Keep the smallest candidate in `best[j]`. Print `best[n]`, or `-1` if it is impossible.

**Why it is right.** Every layout of the first `j` words has a last line, and removing it leaves a layout of the first `i` words. The cost of the layout is the cost of that smaller layout plus the last line, so the cheapest layout of `j` words uses a cheapest layout of some `i` words. Trying every `i` therefore finds it, and cheapest-so-far is all `best[i]` has to remember. Greedy fails the example because its first choice, the fullest first line, is not part of any cheapest layout. A word wider than `W` fits on no line, so the table cannot get past it, and `best[n]` stays impossible.

**Cost.** Each word is at least 1 wide and each gap is 1, so a line of `k` words is at least `2k - 1` wide, a line of width at most `W` holds at most `(W + 1) / 2` words, and each `j` looks back at most that far. Time is O(n × min(n, W)) in the **worst case**, and space is O(n) for `best`.
