Keep `table[m]`, the ways to climb exactly `m` stairs, with `table[0] = 1`. A way to climb `m` stairs ends with some last move of size `s`, so `table[m]` is the sum of `table[m - s]` over the step sizes with `s <= m`, taken modulo 1000000007. Fill `m` from 1 to `N` and print `table[N]`.

**Why it is right.** The ways that end with a move of size `s` are exactly the ways to climb `m - s` followed by that move, so each way is counted once under its last move. Two ways that differ only in order end differently or earlier differently, so they are counted separately, as the statement says. An entry that no move can reach stays 0, which also covers a step larger than `m`.

**Cost.** The table has `N + 1` entries and each looks at every step size, so time is O(N × S) in the **worst case** for `S` step sizes, and space is O(N). The plain recursion makes the same calls over and over: with steps 1 and 2 the number of calls for `ways(n)` obeys `c(n) = 1 + c(n-1) + c(n-2)` from `n = 2` on, so it grows like the Fibonacci numbers and is exponential in `N`. A memoised recursion, as `functools.cache` would give, does the same work as the table, one computation per different `N`, but it nests `N` calls deep, and the table does not.
