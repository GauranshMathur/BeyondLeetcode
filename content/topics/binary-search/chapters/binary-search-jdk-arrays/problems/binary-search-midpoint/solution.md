`naive` is the two-line recipe from the statement: add, wrap into the signed 32-bit range, then divide by 2 and drop the fraction toward zero. Go's `int32(l + h)` wraps by itself. In TypeScript, `(l + h) | 0` wraps, and `Math.trunc` drops the fraction. In Python the wrap is `(sum + 2**31) % 2**32 - 2**31`, and the division has to truncate toward zero, which `//` does not do for a negative number (`-3 // 2` is `-2`), so negate, divide and negate back.

`mid` has several correct forms. `low + (high - low) / 2` never makes a number bigger than `high`. `(low + high) >>> 1` works in Java because two non-negative ints sum to at most 4,294,967,294, which fits in 32 bits when read as unsigned, and an unsigned shift right by one halves it. In TypeScript, `>>>` does the same thing on the 32-bit pattern. In Python and in Go, with 64-bit integers, a plain sum cannot overflow at all, but writing `>> 1` on the sum is how the JDK and Go's own `sort.Search` do it, and the later Problems reuse `mid`.

The trap is any midpoint that adds before it narrows, in a language whose integers are 32 bits. Both commands run in constant time and space.
