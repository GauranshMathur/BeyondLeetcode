First find the cut with `rotation`. A rotated array is a sorted array read from a shifted start: if the smallest item is at index `start` and the array has `n` items, then position `p` of the sorted order sits at index `(p + start) % n` of the array. Now run the search from the first Chapter over positions `0..n-1`, converting a position to an index before you read an item. If the item at that index is below `X`, move `low` up; if above, move `high` down; if equal, return that index (not the position). If the range runs out, print `-1`. An empty array has no cut, so `rotation` returns `-1` and `rsearch` prints `-1` too.

The cut is one `O(log n)` search and the search itself is another, so the **worst case** is `O(log n)` with constant extra space. Common slips: returning the position instead of the index, and forgetting the `% n` so that the index runs off the end of the array.
