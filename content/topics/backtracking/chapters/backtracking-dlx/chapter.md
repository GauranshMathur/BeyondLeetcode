# Knuth's dancing links: a rule for where to branch

Some problems are not about listing everything. They ask for the arrangements that obey every rule: place eight queens so none attack each other, or fill a board with pieces that must not overlap. They are **constraint puzzles**. The loop is the same as before, but now there are two questions: how to undo a choice cheaply, and which choice to make first. Donald Knuth's paper "Dancing Links" (arXiv, November 2000, version 1) is about both. This Chapter reads it. In the Problems you place queens with the paper's cheapest undo, and then solve exact cover with its rule for choosing where to branch.

## What backtracking is, and two ways to undo

The paper's first page names its subject: "Backtracking, also called depth-first search, will be the focus of the present paper." ([page 1](https://arxiv.org/pdf/cs/0011047v1#page=1)) And it names the two ways to keep the state straight as the search goes down and comes back: "In simple situations we can simply maintain a stack that contains snapshots of the relevant state information at all ancestors of the current node in the search tree. But the task of copying the entire state at each level might take too much time. Therefore we often need to work with global data structures, which are modified whenever the search enters a new level and restored when the search returns to a previous level." ([page 1](https://arxiv.org/pdf/cs/0011047v1#page=1)) The pip Chapter took the first way. The queens program below takes the second.

## Dijkstra's queens

The paper describes an older program for the eight queens puzzle. "Dijkstra's recursive procedure for the queens problem kept the current state in three global Boolean arrays, representing the columns, the diagonals, and the reverse diagonals of a chessboard" ([page 2](https://arxiv.org/pdf/cs/0011047v1#page=2)), and the way it undid a move is the whole technique: "When Dijkstra tentatively placed a queen, he changed one entry of each Boolean array from true to false; then he made the entry true again when backtracking." ([page 2](https://arxiv.org/pdf/cs/0011047v1#page=2)) That is choose, explore and undo with no copy at all: placing a queen sets three flags, taking it back clears them. The paper's own technique, which gives it its name, does the same for a doubly linked list. It uses two operations, which the paper numbers (1) and (2). The first is "remove x from the list; every programmer knows this." and the second "will put x back into the list again." ([page 1](https://arxiv.org/pdf/cs/0011047v1#page=1)) The paper explains the name this way: "This process causes the pointer variables inside the global data structure to execute an exquisitely choreographed dance; hence I like to call (1) and (2) the technique of dancing links." ([page 2](https://arxiv.org/pdf/cs/0011047v1#page=2)) The Problems use plain arrays of flags, as Dijkstra did, not linked lists.

## Exact cover

The paper's main example is one problem that many puzzles reduce to: "Given a matrix of 0s and 1s, does it have a set of rows containing exactly one 1 in each column?" ([page 2](https://arxiv.org/pdf/cs/0011047v1#page=2)) Its small example matrix has an answer: it "has such a set (rows 1, 4, and 5)." ([page 2](https://arxiv.org/pdf/cs/0011047v1#page=2)) The method is the same loop, which the paper calls algorithm X: "Otherwise choose a column, c (deterministically)." "Choose a row, r, such that A[r, c] = 1 (nondeterministically)." "Include r in the partial solution." ([page 4](https://arxiv.org/pdf/cs/0011047v1#page=4)) Choosing a column fixes what must be decided next; choosing a row in it is the fork. After a row is included, the columns it covers, and the rows that clash with it, are out of the problem, and the search repeats on what is left.

## Which column to pick

The paper's point is that the first question matters as much as the loop: "Any systematic rule for choosing column c in this procedure will find all solutions, but some rules work much better than others." ([page 4](https://arxiv.org/pdf/cs/0011047v1#page=4)) It measures it on a puzzle of its own, to find all the "ways to place the 12 pentominoes into a chessboard leaving the center four squares vacant." ([page 3](https://arxiv.org/pdf/cs/0011047v1#page=3)) Taking the first uncovered column in order "leads to a search tree with 9,015,751 nodes." ([page 4](https://arxiv.org/pdf/cs/0011047v1#page=4)) The rule it recommends is "we want to choose at each stage a column with fewest 1s in the current matrix A." ([page 4](https://arxiv.org/pdf/cs/0011047v1#page=4)) The reason is in the numbers. Three runs of the puzzle with the first rule have trees of "103,005 nodes and 19 solutions (X at 23);", "106,232 nodes and 20 solutions (X at 24);" and "126,636 nodes and 26 solutions (X at 33, P not flipped)," "when columns are chosen lexicographically." ([page 4](https://arxiv.org/pdf/cs/0011047v1#page=4)) The same three with the fewest-1s rule have "10,421 nodes (X at 23);", "12,900 nodes (X at 24);" and "14,045 nodes (X at 33, P not flipped)," ([page 5](https://arxiv.org/pdf/cs/0011047v1#page=5)) between 8 and 10 times fewer (arithmetic on the six numbers). A column with few rows is a fork with few branches. A column with none is a dead end found at once: "If column c is entirely zero, there are no subalgorithms and the process terminates unsuccessfully." ([page 4](https://arxiv.org/pdf/cs/0011047v1#page=4)) Choosing it first is pruning by order, and it costs nothing in correctness: every rule finds all the solutions.

## What it costs

Exact cover can take exponential time in the **worst case**; the number of nodes is what the rule changes, not that bound. For `queens N` each row tries at most N columns, so there are at most N^N paths without the flags, and the flags cut it to the placements that are safe so far (arithmetic). Each step checks and sets three flags in O(1) in the **worst case**.

## What the Problems build

`queens N` counts the ways to place N queens and prints the first, using three arrays of flags as in the paper. It is a Core Problem. The Extra Problem `exact` solves an exact cover from a list of rows with the fewest-1s rule, and prints the solutions and the number of nodes in its search, so the order of the choices shows in the count. Its first example is the paper's matrix, whose answer is rows 1, 4 and 5.
